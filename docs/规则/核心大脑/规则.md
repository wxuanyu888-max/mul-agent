## 业务约束

### 参数范围

| 参数 | 类型 | 取值范围 | 默认值 | 说明 |
|------|------|----------|--------|------|
| max_team_size | int | 1-100 | 10 | 最大团队成员数 |
| command_timeout | int | 1-300 | 30 | 命令执行超时秒数 |
| snapshot_interval | int | 1-1000 | 100 | 多少次操作后创建快照 |

### 核心逻辑

1. 核心大脑是系统的唯一决策中心
2. 核心大脑通过heart路由进行自省和进化
3. 核心大脑通过create_user路由进行Agent分裂
4. 所有配置变更都需要记录版本快照

### 边界情况

- 达到最大团队数量时，禁止创建新Agent，返回错误
- 配置修改失败时，自动回滚到上一个快照
- 工具执行超时时，返回超时错误，保留部分输出

### 判断规则

| 场景 | 判断条件 | 结果 |
|------|----------|------|
| Agent分裂 | 任务复杂度 > 阈值 且 团队未满 | 创建新Agent |
| 自我进化 | 连续失败 >= 3 次 | 触发heart自省 |
| 配置回滚 | 修改失败 | 恢复到上一个快照 |

## 技术约束

### 技术选型原则

- 优先使用Python标准库，减少外部依赖
- 配置存储使用JSON格式，便于Agent解析和修改
- CLI框架使用Click或Typer

### 架构原则

- 分层架构：CLI入口 -> Agent核心层 -> 工具层 -> 存储层
- 配置驱动：规则尽量放配置，代码保持灵活性

### 集成约束

- MCP工具：保持现有chrome-devtools、web-search兼容性
- 存储：JSON文件存储，支持未来扩展到数据库
